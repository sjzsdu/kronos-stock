# 功能规范：用户系统

**功能分支**: `001-user-system`  
**创建日期**: 2025-10-01  
**状态**: 草案  
**输入**: 用户描述："我想给当前项目增加一套用户系统"

## 概述

为 Kronos 股票预测平台实现完整的用户管理系统，支持用户注册、认证、档案管理和基于角色的访问控制。该系统将与现有股票预测功能集成，提供个性化的用户体验。

## 用户场景与测试

### 主要用户流程：新用户注册
1. 用户访问注册页面
2. 用户提供邮箱、密码和基本档案信息
3. 系统验证输入并创建账户
4. 用户收到确认邮件
5. 用户登录并访问个性化仪表板

### 认证流程
1. 现有用户访问登录页面
2. 用户输入凭据（邮箱/密码）
3. 系统验证并创建会话
4. 用户被重定向到相应角色的仪表板

### 档案管理流程
1. 已认证用户访问档案设置
2. 用户更新个人信息和偏好设置
3. 用户可以通过当前密码验证更改密码
4. 更改被保存并用户收到确认

### 管理员管理流程
1. 管理员用户访问用户管理界面
2. 管理员可以查看所有用户、更改角色、禁用账户
3. 管理员可以查看用户活动和预测历史
4. 系统维护管理员操作的审计日志

## 功能需求

### 认证与授权
- **FR-001**: 系统必须支持邮箱/密码认证并使用安全的密码哈希
- **FR-002**: 系统必须实现基于角色的访问控制（用户、高级用户、管理员）
- **FR-003**: 系统必须维护具有可配置超时的用户会话
- **FR-004**: 系统必须通过邮件提供密码重置功能
- **FR-005**: 系统必须强制执行密码强度要求（8+字符、大小写混合、数字）

### 用户档案管理
- **FR-006**: 系统必须允许用户创建和编辑包含姓名、邮箱、偏好的档案
- **FR-007**: 系统必须存储用户预测历史和收藏夹
- **FR-008**: 系统必须提供包含个性化内容的用户仪表板
- **FR-009**: 系统必须允许用户管理通知偏好设置
- **FR-010**: 系统必须支持用户账户停用/删除

### 与股票系统集成
- **FR-011**: 系统必须将预测与已认证用户关联
- **FR-012**: 系统必须跟踪用户预测准确性和性能指标
- **FR-013**: 系统必须基于用户活动提供个性化股票推荐
- **FR-014**: 系统必须基于用户角色实现使用限制（免费用户 vs 高级用户）
- **FR-015**: 系统必须维护用户的股票关注列表和提醒

### 管理功能
- **FR-016**: 系统必须提供用户管理的管理员界面
- **FR-017**: 系统必须生成用户活动报告和分析
- **FR-018**: 系统必须支持批量用户操作（导入/导出）
- **FR-019**: 系统必须维护全面的审计日志
- **FR-020**: 系统必须提供用户相关指标的系统健康监控

## 关键实体

### 用户实体 (User)
- **user_id** (主键): 唯一标识符
- **email**: 用户邮箱地址（唯一，必需）
- **password_hash**: 安全哈希密码
- **full_name**: 用户显示名称
- **role**: 用户角色（普通用户、高级用户、管理员）
- **is_active**: 账户状态标记
- **created_at**: 账户创建时间戳
- **last_login**: 最后成功登录时间戳
- **email_verified**: 邮箱验证状态

### 用户档案实体 (UserProfile)
- **profile_id** (主键): 唯一标识符
- **user_id** (外键): 关联到用户表
- **phone**: 可选电话号码
- **timezone**: 用户时区偏好
- **notification_preferences**: 通知设置的JSON字段
- **subscription_tier**: 订阅层级（免费/高级/企业）
- **subscription_expires**: 高级订阅过期日期

### 用户会话实体 (UserSession)
- **session_id** (主键): 会话标识符
- **user_id** (外键): 关联到用户表
- **session_token**: 安全会话令牌
- **created_at**: 会话创建时间
- **expires_at**: 会话过期时间
- **ip_address**: 客户端IP地址
- **user_agent**: 客户端浏览器信息

### 用户预测实体 (UserPrediction)
- **prediction_id** (主键): 链接到现有预测系统
- **user_id** (外键): 关联到用户表
- **created_at**: 用户进行预测的时间
- **is_favorite**: 用户标记的收藏预测
- **notes**: 用户对预测的个人笔记

### 关注列表实体 (Watchlist)
- **watchlist_id** (主键): 唯一标识符
- **user_id** (外键): 关联到用户表
- **stock_code**: 被关注的股票代码
- **alert_thresholds**: 价格提醒的JSON字段
- **created_at**: 股票添加到关注列表的时间

## 非功能性需求

### 安全需求
- **NFR-001**: 所有密码必须使用bcrypt哈希，最少12轮加密
- **NFR-002**: 会话令牌必须是密码学安全的，并在24小时内过期
- **NFR-003**: 认证端点必须实现速率限制（5次尝试/分钟）
- **NFR-004**: 管理员操作必须需要额外认证（推荐双因素认证）
- **NFR-005**: 用户数据必须仅通过HTTPS传输

### 性能需求
- **NFR-006**: 用户登录必须在正常负载下2秒内完成
- **NFR-007**: 用户仪表板必须在3秒内加载个性化数据
- **NFR-008**: 系统必须支持1000+并发认证用户
- **NFR-009**: 用户数据的数据库查询必须通过适当索引进行优化

### 可扩展性与可靠性
- **NFR-010**: 用户系统必须与现有Flask蓝图架构无缝集成
- **NFR-011**: 数据库迁移必须是可逆和可测试的
- **NFR-012**: 系统必须优雅地处理用户数据损坏或丢失场景
- **NFR-013**: 用户会话必须在应用重启后持续存在（数据库支持）

## 集成点

### 现有系统集成
- **股票预测服务**: 将预测与已认证用户关联
- **API端点**: 添加认证中间件保护敏感端点
- **HTMX视图**: 实现用户感知的UI组件和个性化内容
- **数据库**: 使用用户相关表扩展现有SQLAlchemy模型

### 外部依赖
- **邮件服务**: 用于注册/密码重置邮件的SMTP配置
- **会话存储**: 推荐Redis进行会话管理（可选的数据库升级路径）
- **日志系统**: 增强认证和用户活动的日志记录
